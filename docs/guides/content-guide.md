# 内容、图解与质量规范

## 文章应该解释什么

遵循 [Olah-style Paper Posts](https://github.com/1998x-stack/Olah-style-posts) 的叙事原则，但不要把论文专用的实验表格/指标要求机械地套在操作系统课程上。

每章优先保持以下顺序：读者的问题 → 关键抽象 → 数据/控制流 → 必要的命令或实验 → 适用条件与局限 → 复盘。分清**概念图**与**内核实际实现**；术语、接口、版本敏感结论应以官方文档、源码或标准为依据。

## 版本与可验证性

- 声称某 Linux 版本“默认使用”某算法或接口时，给出版本及参考来源；没有核对来源时不要写成永恒结论。
- 命令应标注平台、权限、依赖与潜在风险；内核模块、驱动、容器隔离、eBPF 和系统配置变更先在 QEMU/VM 内进行。
- 示例输出、性能数字、轶事与演示代码不能自动证明普遍性能或现实比例。必要时明确“示意”“预期输出”“未在此环境验证”。
- 代码是否能编译运行须用实测报告支持。章节中尚未建立完整可运行的实验验证集，请勿将代码框架误称为开箱即用的生产程序。

## 视觉与可访问性

- 每页仅一个 H1，正文使用可直接链接的 H2 锚点；页内目录使用真实锚点，前后导航不能用 `javascript:void(0)`。
- 语义标签使用 `main`、`article`、`nav`、`figure`、`figcaption`；图片必须有描述性 `alt`，SVG 至少有 `title` 与 `desc`。
- 技术图回答一个明确问题，确保**即使没有 JavaScript**也能理解。先写图注再绘图，区分抽象流程和具体内核实现。
- CSS 存于 `assets/css/site.css`；新组件应沿用该文件的主题变量。保证可见焦点、正文对比度、360/390 px 手机宽度和打印视图；宽代码与表格在自身区域滚动。

## 发布前检查

运行 `python3 scripts/check_site.py`，逐个浏览章节首屏、正文、锚点、导航及代码块。浏览器测试应覆盖 1440/390/360 px、键盘焦点、打印和图片加载。静态检查通过**不等于**浏览器 QA、实验复现或 GitHub Pages 部署验证通过。

若改动 `courses.json` 的章节顺序或标题，应同步更新首页、README 和章节导航，避免多处目录不一致。

当前改造仅对页面结构、导航与可阅读性建立基线；原文章中的历史叙述、内核 API 使用和示例代码仍需按章节进行后续事实与运行验证。


## 第二轮工程验收

- 首页入口与课程分组以 `index.html` 和 `courses.json` 为准；新增章节时同步更新两者。
- 实验文档遵循 [实验可复现规范](experiment-standard.md)，并提供预期结果与清理步骤。
- 本地运行 `python3 scripts/check_site.py`；浏览器冒烟测试运行 `npm install` 后执行 `npm run test:browser`，默认要求本地静态站点监听 `127.0.0.1:4173`。
- GitHub Actions 的静态检查与 Playwright 检查是不同层级的门禁；通过冒烟测试不等于完成视觉回归或实验实测。
