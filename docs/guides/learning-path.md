# 28 章学习路径

按知识依赖推进，而不是把所有 Linux 接口一次记住。

## 01–07：建立底层地图

先问：**操作系统为何需要控制硬件与用户程序之间的边界？** 阅读 OS 角色、硬件架构、内核类型、用户态与内核态、启动链路，再搭建 QEMU/GDB/xv6 的安全实验环境。完成这一阶段，尝试画出“应用程序 → 系统调用 → 内核 → 设备”的路径。

## 08–14：理解资源如何分配

以进程为线索，将线程、调度、同步、虚拟内存、物理页管理和文件系统串起来。练习用自己的话解释一次 `fork()`、缺页异常或文件打开所涉及的内核对象；注意“模型示意”和“当前 Linux 某版本实现”的区别。

## 15–20：解释可观测的系统行为

学习 I/O 模型、驱动、中断、计时、网络协议栈与 eBPF。先阅读工具的权限要求，在虚拟机里用 `strace`、`perf` 或 `bpftrace` 观察一个具体问题；保存操作步骤、环境与结果，避免将示例输出视为普适基准。

## 21–28：建立工程判断

用虚拟化、容器、内核调试和性能分析理解隔离、故障定位与权衡；再阅读小型 OS 项目和综合项目。建议每个项目留下三项交付物：**环境说明、可复现步骤、预期与实际结果**。

## 学习节奏示例

每章用三轮读法：第一轮回答“为什么”；第二轮画出“机制与状态变化”；第三轮在受控环境验证一项可观察现象。遇到复杂命令时，可以先只阅读并标注依赖，不必在宿主机直接执行。
