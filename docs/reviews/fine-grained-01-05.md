# 第 01–05 章逐篇精细化复核

更新日期：2026-11-21

## 范围与方法

按章节顺序，逐篇提交，不批量重写已有内容。每篇新增一个围绕具体问题展开的 **机制追踪 / 故障边界推导**，以及一个明确环境、步骤、预期、局限与清理要求的 **微实验或分析练习**。

所有章节均保留原始 `01.html`–`05.html` 地址、目录锚点、前后章节链接和既有图示。新增的教学段落不声称对某一 Linux 版本的完整调用栈或对未实测环境的性能结果作出保证。

| 章节 | 机制追踪 | 实验与验收 | 本次技术校准 |
| --- | --- | --- | --- |
| 01 · 什么是操作系统 | `read()` → fd 表 → 内核文件对象 → 文件系统/设备/页缓存 → 返回 | Linux procfs 只读观察；提醒 `/proc/self` 的进程语义 | `read()` 不一定触发磁盘 I/O，打开文件描述符不等于设备地址 |
| 02 · 硬件架构基础 | 地址翻译 / TLB → CPU 缓存 → 页故障的层级区别 | `perf stat` 的软件事件与硬件事件观察，允许权限/设备差异 | cache miss、TLB miss、page fault 不能混为同一种事件 |
| 03 · OS 内核架构 | 假想文件系统服务故障在宏/微内核保护域中的传播与恢复 | 绘制保护边界、调用/IPC、共享设备与恢复策略，不要求 root | seL4 的证明对象和 DMA/硬件/启动假设要分开描述 |
| 04 · 用户态与内核态 | x86-64 `write()` ABI、入口、参数、返回、errno/短写 | 编译 C 程序、`strace` 观察 `write(1,...,6)`，明确 CI 只验证用户态执行 | 系统调用、特权级切换与任务上下文切换不是同一事件 |
| 05 · 引导与初始化 | 固件/Bootloader/initramfs/真实根/PID 1 逐段排查 | 只读检查 EFI、cmdline、root mount、PID 1 与 systemd unit | 区分 `After=` 的排序、`Requires=`/`Wants=` 的依赖与失败行为 |

## 前端与自动化验收

- 新增复用组件样式：`.deep-dive`、`.practice-card`、`.causal-steps`，保留手机端滚动代码、键盘可打开的 details、语义标签和章节目录。
- Playwright 冒烟测试新增断言：第 01–05 章在 360px 和 1440px 视口下，每篇恰有一个机制追踪与实验卡片；第 01 章的 details 可展开。
- 所有新增实验文本明确是否需要 root；未授权的 `perf` 采样、没有 systemd 的主机以及未安装 `strace` 的环境都要按预期失败/跳过处理，不能强行修改安全配置。
- 五个 evidence JSON 分别新增一条与本篇机制/实验直接对应的主源或权威接口文档。
- GitHub Actions 运行情况，以本批最后一个提交对应的 workflow run 为准。

## 验证边界

本轮是在 GitHub 上更新静态 HTML、证据 JSON、共享样式与浏览器自动化检查。未宣称已在真实硬件上测量 TLB、CPU cache miss 或系统调用成本；未宣称所有只读实验都在某特定用户主机上运行。第 04 章的独立 `scripts/test_labs.py` 用户态编译/执行检查与 `strace` 的实际追踪是两项不同验证。
