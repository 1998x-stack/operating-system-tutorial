# 第 27–28 章逐篇精细化复核

更新日期：2026-11（第五批）

## 范围与方法

延续 [第 19–26 章](fine-grained-19-26.md) 的做法，按章节顺序逐篇提交，不批量重写已有内容。每篇新增一个围绕具体问题展开的 **机制追踪**、一个明确环境/步骤/预期/清理要求的 **只读微实验**，并补一张原创解释图。新增段落全部落在既有 `27.html`–`28.html` 的章节目录、锚点、前后导航与图示范围内。

新增内容不声称对某一 Linux 版本给出完整调用栈，也不把只读观察实验写成已经实测的内核运行时结论。

| 章节 | 机制追踪 | 只读微实验 | 本次技术校准 |
| --- | --- | --- | --- |
| 27 · 内核设计决策 | 把宏内核/微内核、用户空间铁律与稳定 ABI 争论拆成“目标—约束—替代方案—代价” | `uname`/`/boot/config`/sysfs/`sysctl` 只读核对接口边界与可调参数 | 用户空间 ABI 稳定 ≠ 内核内部 API 稳定；稳定 ABI 换来二进制兼容也换来演进阻力 |
| 28 · 综合项目 | 一个项目从“跑起来”到“可下结论”要区分的证据层级 | 四个项目所需工具链与前提（`perf`/`bpftrace`/BTF/`qemu`/xv6）只读核对 | 火焰图宽色块只是采样归属，不等于“可优化”；工具存在 ≠ 项目跑通 |

## 新增图示

- `assets/diagrams/kernel-tradeoffs.svg`（27）：把宏内核与微内核放进同一组约束坐标比较，并区分用户空间 ABI 与内核内部 API 两条承诺不同的边界。
- `assets/diagrams/project-loop.svg`（28）：四个综合项目各自的证据产出，以及共用的“目标—实现—证据”验证环。

两图均为本项目新绘制的解释性概念图，图注已注明是简化示意，坐标轴无量化刻度，不代表某一内核版本的具体实现或性能结论。

## 前端与自动化验收

- 新增复用组件沿用 `.mechanism-figure`、`.deep-dive`、`.practice-card`、`.causal-steps`，保留手机端滚动代码、关于代码块内 `&lt;` 的转义、语义标签与章节目录。
- 以本地 `http.server` + Playwright 在 1440/390/360 px 下抽查第 27、28 章：无横向溢出、无 JS 报错、无断图，图片（图示）正常加载，每页恰有一个机制追踪与一个只读实验卡片，`figcaption` 非空。

## 验证边界

本轮更新的是静态 HTML、新增 SVG 与文档记录。新增实验均为只读观察，**未**在真实硬件或隔离 VM 上完成 eBPF 挂载、字符设备模块加载、xv6 COW 实现或火焰图性能对比；也未宣称所有只读命令都在某个特定主机与内核版本上执行成功。
